## Contract and identity

Source: [current official Goekua API](https://goekua.com.py/api-docs.html), updated 15 July 2026, read 4 October 2026.
Provider DTOs live in lib/goekua.ts; domain mapping/validation lives in lib/goekua-payload.ts.

Invoice serialization uses user.lastName, client.isContributor, establishment.idSifen,
item code/measureUnit/amount/unitPrice/taxRate, and payment paymentType/charge/currency/currencyRate.
Obsolete quantity/vatRate/contributor/establishment.id/payment type/amount payload names and timbrado are removed.
Credit-note serialization is a separate DTO with cdcElectronicDocumentAttached, emissionMotive,
user, establishment, items containing only code/amount/unitPrice, pointOfExpedition and documentNumber.
It does not send invoice-only client/payment/tax structures or referencedCdc.

The documented create response provides an opaque id. It is stored only in goekua_document_id.
An optional explicit CDC is accepted only when actually present and shaped as 44 digits; this validation
does not establish DNIT approval. Invalid/missing CDC leaves cdc null and retains the provider ID.
Optional XML/KUDE URLs are stored only when returned. Consultation's inline XML is not a URL and is not
written into xml_url. Consultation has a distinct response type, without a made-up create ID.

There is no documented provider-ID-to-CDC lookup implemented. A saved provider ID without CDC means
reconciliation required. FE and NC server actions reject another issuance, and the UI shows the ID
and reconciliation message without an issue button or FE-issued claim. consultarFE refuses that state,
requires a real CDC, and explicitly filters its read and KUDE write by current empresa_id.
Historical invalid CDC values are not backfilled, copied or treated as fiscal identity.

## Authority and human NC choice

AUTH → tenant → internal lifecycle → existing B10 provenance validator → duplicate metadata →
payload validation → provider → metadata persistence.
Only internally issued FACTURA/NOTA_CREDITO (EMITIDA/COBRADA_PARCIAL/COBRADA) can reach the provider.
The NC source must be a valid same-company issued invoice, pass canonical provenance and contain a
real CDC; absent/invalid CDC returns the requested exact pre-HTTP message.

No existing NC motive field was found. The existing fiscal control now requires a blank-by-default
human selection from motives 1–8, with no arbitrary default. Each NC line also requires a human
selection of the exact source invoice line, since the distinct provider NC contract references its code.
Invoice line code is the existing ERP line ID; NC code is the selected source line ID. No inferred
description matching, SKU creation, quantity allocation ledger or new NC lifecycle is introduced.
The tool caller must supply the explicit motive and source item IDs and reaches the same authority.

The selected motive, source CDC and serialized NC items are preserved in the existing append-only
log_audit_event JSON detail (sifen.credit_note.requested, including tenant/document/source IDs).
This is a request record, not a claim of completed issuance. Recording failure blocks HTTP.
It neither overloads notes nor adds another column. The provider ID stored on the document identifies
the external create result; successful fiscal actions leave status, totals, collection and treasury intact.

## Mandatory data gaps — intentionally fail closed

Existing internal numbering V-xxxxx is not a fiscal number. It is not stripped, padded or silently
converted. The adapter requires a factual 7-digit fiscal document number; B10 does not create a
fiscal numbering engine or mutate existing codes. Consequently documents generated by the current
internal numbering path cannot yet issue fiscally. This is an explicit integration limitation.

Issuer name/surname/document and establishment house/city/contact/unit configuration is required,
without fabricated RUC, address, unit or identity defaults:
GOEKUA_USER_NAME, GOEKUA_USER_LAST_NAME, GOEKUA_USER_DOCUMENT_TYPE,
GOEKUA_USER_DOCUMENT_NUMBER, GOEKUA_ESTABLISHMENT_ID, GOEKUA_ESTABLISHMENT_ADDRESS,
GOEKUA_ESTABLISHMENT_HOUSE_NUMBER, GOEKUA_ESTABLISHMENT_CITY_ID,
GOEKUA_ESTABLISHMENT_PHONE, GOEKUA_POINT_OF_EXPEDITION, GOEKUA_MEASURE_UNIT.
GOEKUA_USER_EMAIL may explicitly override actual company email; establishment denomination may use
GOEKUA_ESTABLISHMENT_NAME or actual company name. Company email must exist.

The former hardcoded commercial integration values now require explicit configuration:
GOEKUA_TRANSACTION_TYPE, GOEKUA_OPERATION_CONDITION_TYPE, GOEKUA_EMISSION_TYPE,
GOEKUA_PRESENCE_INDICATOR_TYPE and GOEKUA_PAYMENT_TYPE. These are integration policy, not inferred
per-document commercial facts; configure them only for documents where those facts hold.
Only the existing cash payment mode is represented; absent card/cheque fields are not invented.
Credit condition requires actual doc.due_date and sends expirationDate. PYG rate is 1;
foreign currency requires positive GOEKUA_CURRENCY_RATE. Non-contributor identification is not
represented in the existing domain and is rejected; contributor RUC/name/address are required.
No secrets, environment configuration or production fiscal/customer data were read or modified.
